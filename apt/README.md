# 우리 단지 거래 추적 — 시범한빛마을 KCC스위첸

네이버 부동산에 올라온 **매물이 사라지면 거래된 것으로 추정**하고, 국토교통부 **실거래 신고가 올라오면 맞춰 보는** 앱이에요.
우리 단지(동탄 반송동 시범한빛마을 KCC스위첸, 484세대)와 같은 마을 네 단지(동탄아이파크, 금호어울림, 삼부르네상스, 한화꿈에그린)를 같이 봐요.

- Android 앱: https://github.com/YoSebChoi/YoSebChoi/releases/download/apt-apk/apt-watch.apk
  (폰에서 받고 "출처를 알 수 없는 앱" 허용. 다음부터는 앱이 새 버전을 물어봐요)
- 웹: `https://yosebchoi.github.io/YoSebChoi/apt/` — 실거래와 블로그만 보여요. **매물 추적은 앱에서만 돼요.**

## 요구사항 정리

| 요구 | 어떻게 |
| --- | --- |
| 실거래 확인 | 국토교통부 아파트 매매 실거래가(공공데이터포털)를 GitHub Actions가 매일 받아서 앱에 넣어요 |
| 매물이 보이다 사라지면 거래로 추정 | 앱이 네이버 부동산 매물을 하루 두 번(앱을 열 때도) 확인하고, 이전 기록과 비교해요 |
| 네이버 정보 | 매물: 폰이 직접 네이버 부동산(m.land.naver.com)을 읽어요. 블로그: NAVER API HUB 블로그 검색(ivf-blog 때와 같은 방식) |
| 기존 앱들과 같은 모양 | `apt/index.html` 한 파일 웹앱 → `docs/apt/`(GitHub Pages), `apt-app/`은 그 페이지를 띄우는 Capacitor 앱, 서명 키·업데이트 방식도 같아요 |

### 왜 매물은 폰에서만 다루나요

- 2026년 5월, 네이버페이 부동산 매물을 크롤링해 공개 게시한 업체에 데이터베이스권 침해로 8천만 원 배상 판결이 확정됐어요.
  이 저장소는 공개라서, 매물을 Actions로 모아 커밋하면 그대로 공개 게시가 돼요.
- 그래서 매물은 **내 폰이 사람이 보는 정도로 천천히** 읽고(단지마다 한두 쪽, 요청 사이 1~3초, 하루 두 번), 기록은 **폰에만** 저장해요.
  저장소와 웹에는 공공데이터(실거래)와 블로그 제목·링크만 올라가요.
- 가정·모바일 IP라서 GitHub 서버보다 네이버에 막힐 일도 적어요.

## 화면

| 탭 | 내용 |
| --- | --- |
| 요약 | 지금 매물 수·최저 호가·30일 거래 추정, 매물 수 추이, 최근 변화(사라짐·새 매물·가격 변경·다시 올라옴·실거래 확인) |
| 매물 | 단지별 지금 매물. 같은 집을 여러 중개사가 올린 건 한 집으로 묶고, 등록 며칠째·가격 내림을 보여요. 누르면 중개사별 매물과 네이버 링크 |
| 거래 추정 | 사라진 집 목록: `거래 추정` → 실거래와 맞으면 `실거래 확인`, 다시 올라오면 `재등록` |
| 실거래 | 단지·면적별 최근 3년 그래프(지금 호가 표시), 해제 거래 표시 |
| 블로그 | 단지별 블로그 글. 기본은 매매·시세 이야기만(인테리어·청소 글 빼기) |

### 거래 추정 규칙 (`apt/tracker.js`)

1. 같은 단지·동·층·전용면적·방향 매물은 한 집이에요 (중개사 여러 곳 → 한 집).
2. 그 집 매물이 **성공한 확인 두 번 연속, 마지막으로 본 뒤 20시간 넘게** 안 보이면 `거래 추정`.
3. 마지막으로 본 날 30일 전~20일 뒤에, 같은 단지·면적(±1㎡)·층(저/중/고는 건물 높이의 1/3씩)에서 호가의 85~103%로 신고된 실거래가 있으면 `실거래 확인`.
4. 21일 안에 같은 집이 다시 올라오면 `재등록`(거래 아님).
5. 매물이 5건 넘던 단지가 갑자기 0건이면 막힌 것일 수 있어 다음 확인까지 믿지 않아요. 실패한 확인은 아무것도 사라지게 하지 않아요.

## 처음 설정

1. 앱 설치 → ⚙ 설정 → **주변 단지 찾기**: 시범한빛마을 다섯 단지가 자동으로 연결돼요.
   안 되면 네이버 부동산 앱에서 단지 화면의 공유 링크를 복사해 붙여 넣고 「연결하기」.
2. 「앱을 닫아 둬도 확인」 12시간마다(기본), 「매물이 안 보이면 알림 받기」.
3. 기록은 폰에만 있으니 가끔 **내보내기**로 백업해 두세요(폰을 바꿀 때 「가져오기」).

### 저장소 Secret (Settings → Secrets and variables → Actions)

| 이름 | 쓰임 | 없으면 |
| --- | --- | --- |
| `MOLIT_KEY` | 공공데이터포털(data.go.kr) 「국토교통부_아파트 매매 실거래가 자료」 활용 신청 → 일반 인증키 | 실거래 탭이 비어 있어요 |
| `NCP_API_KEY_ID`, `NCP_API_KEY` | 네이버 클라우드 NAVER API HUB 검색 API 키 (ivf-blog에서 쓴 것과 같은 종류) | 저장소에 있는 블로그 글만 보여요 |
| `ANDROID_SIGNING` | 다른 앱들과 같은 서명 키 | 디버그 키로 서명돼 업데이트 때 다시 설치해야 해요 |

키를 넣은 뒤 Actions → **우리 단지 거래 추적 데이터** → Run workflow. 그다음부터는 매일 06:17에 알아서 받아요.
실거래 지역코드는 화성시 41590에서 시작하고, 2026년 2월 동탄구 신설로 바뀌었으면 반송동 거래가 나오는 코드를 스스로 찾아 기록해요(`apt/data/trades.json`의 `months`).

## 파일

| 파일 | 내용 |
| --- | --- |
| `apt/index.html` | 화면 (한 파일) |
| `apt/tracker.js` | 매물 비교·거래 추정·실거래 맞추기 (화면과 테스트가 같이 씀) |
| `apt/data/complexes.json` | 추적할 단지: 이름, 실거래 단지명 패턴(`molit`), 네이버 이름 패턴, 블로그 검색어 |
| `apt/fetch_trades.py` | 실거래 → `apt/data/trades.json` (반송동 전체, 지난 달은 한 번만, 최근 4개월은 매번) |
| `apt/fetch_blog.py` | 블로그 → `apt/data/blog.json` (제목·링크·날짜·블로그 ID만, 본문 안 받음) |
| `apt/build.py` | `docs/apt/` 만들기 (실거래를 단지에 묶고, 아이콘·서비스 워커·매니페스트) |
| `apt-app/` | Android 앱. `AptNet` 플러그인(네이버 부동산만 요청 가능)과 `SnapshotWorker`(백그라운드 확인·알림) |

```sh
node --test apt/tests/tracker.test.mjs     # 추정 규칙 테스트
MOLIT_KEY=... python3 apt/fetch_trades.py
python3 apt/fetch_blog.py                  # NCP_API_KEY_ID / NCP_API_KEY (또는 키를 붙여 주는 프록시)
python3 apt/build.py
node apt/check/check_app.mjs               # 브라우저로 웹 화면 + 가짜 네이버로 앱 흐름 확인 (playwright 필요)
python3 apt/assets/make_icon.py && python3 apt-app/make_icons.py   # 아이콘
```

## 한계

- 네이버 부동산에는 공식 API가 없어요. 모바일 웹이 쓰는 주소(`m.land.naver.com/complex/getComplexArticleList`)를 읽는데,
  네이버가 바꾸면 설정 → 최근 확인 기록에 오류가 보여요. 그때는 `apt/index.html`의 `LIST_URL`만 고치면 앱 재설치 없이 바로 반영돼요
  (백그라운드 확인은 다음에 앱을 열 때 새 주소를 받아요).
- 매물이 사라지는 이유는 거래 말고도 많아요(광고 기간 끝, 집주인이 거둠, 전세로 돌림). 그래서 실거래와 맞을 때만 `실거래 확인`이에요.
- 실거래는 계약 후 30일 안에 신고돼서, 거래 추정이 확인으로 바뀌는 데 한 달쯤 걸릴 수 있어요.
- 앱을 오래 안 열고 백그라운드 확인도 꺼 두면 그 사이에 올라왔다 사라진 매물은 못 봐요.
